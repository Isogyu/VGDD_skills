# 夜間の運転と朝刊（harness）

- 位置づけ：オーナーが寝ている間に、承認済みの票のキューを無人で回し、朝に「一晩で何が起き、何を確認してほしいか」を読める形にする運転の説明である。最初は設計案として書いたものを、今の実装（`vgdd/scripts/night-runner.sh`・`morning-report.mjs`・`gate-runner.sh --hold`・`release.sh`）に合わせて書き直した。
- 規範は [`vgdd/kernel/SPEC.md`](../vgdd/kernel/SPEC.md)。夜間の代行の規則は SPEC §5・§8・§9 にある。この文書と SPEC が食い違えば、SPEC を正とする。役割の体制と統合の条件は [`governance.md`](governance.md) にある。
- `OBS-033` のような番号は、最初の導入先の記録の番号である。元の記録はこのリポジトリにない（[`kernel.md`](kernel.md) の冒頭に断りがある）。既定の名前（保護領域 `~/tsubuyaki-z3`）は、開発のときの配置の名前で、今の実装の既定の値である。配布の前に変える予定である。
- 前提：**夜間だから緩める規則は一つもない。** gate-runner（統合）、judge、Codex、フック、sandbox、権限ルールは昼と同じである。夜間の代行は、行政の長の役を機械的に代行するスクリプトで、合否や採否を決めない。
- 確かめた範囲：夜間の代行は、最初の導入先で試験運転と夜の運転に使った（スクリプトの頭書きによる。その記録はこのリポジトリにない）。適合性テストの N 群は、夜間の代行の規則を確かめる。朝刊の部品（`morning-report.mjs`）は、適合性テストの対象ではない。

## 1. 全体の流れ

```
 前の晩（人）                    夜（無人）                                    朝（人）
 ┌──────────────┐   ┌─────────────────────────────────────────┐   ┌──────────────┐
 │ キューの案を   │   │ night-runner.sh（オーナーの権限、sandbox の外）     │   │ 朝刊を読む     │
 │ 書く          │   │  前点検 → レーンに票を配る → 作業員を無人で起動     │   │ blocked の裁定 │
 │ オーナーが     │──▶│  → 結果の前検査 → 票を review にして申請          │──▶│ 差し戻しの指示 │
 │ Z3 に置いて承認│   │  → gate-runner の結果を待つ → 次の票 → 止める条件   │   │ release で統合 │
 └──────────────┘   │ gate-runner.sh --hold（常駐。昼と同じ条件で判定）    │   └──────────────┘
                    │ morning-report.mjs（朝。集計 → ローカル LLM → Claude）│
                    └─────────────────────────────────────────┘
```

役割との対応（[`governance.md`](governance.md) §1）：night-runner は行政の長の夜間の代行で、票を配り、申請を置く。実装しない、判定しない、merge しない。作業員は昼と同じ `worker`（無人の `claude -p --agent worker`）である。司法は gate-runner の中の judge と Codex で、昼と同じである。朝刊の部品は書記で、何も決めない。

gate-runner は、night-runner とは別にオーナーが起動しておく。night-runner は gate-runner を起こさず、止めもしない（別のプロセスの独立を守るため）。

## 2. 票のキュー

- **置き場所**：Z3 の `night/queue.json`（オーナーだけが書ける）。行政の長は案を書き、オーナーが中身を見て Z3 に写す。**写した時点が承認**である。行政がキューを書き換える経路はない。
- **形**：

```json
{
  "schema": "vgdd.night-queue.v1",
  "date": "2026-01-01",
  "approved_by": "owner",
  "approved_at": "2026-01-01T23:20:00+09:00",
  "limits": { "parallel": 1, "max_tickets": 6, "until": "06:30", "max_judge_calls": 20,
              "max_tokens_per_ticket": 2000000, "max_tokens_total": 12000000, "min_free_gb": 3 },
  "tickets": [ "T-001", "T-002", "T-003" ]
}
```

- **乗せられる票の条件**（night-runner が main の票を読んで機械的に確かめる。1 つでも外れれば飛ばして、要約に書く）：
  1. `status: ready`、または `in_progress` で差し戻し回数が上限（3）未満。
  2. 仕様の指紋に、オーナーの承認がある（SPEC §4）。
  3. `requirements_source: ticket` で、`unattended: true`。「オーナーの判断が要らない」を、オーナーが票ごとに明示する。依存の追加や削除、push、削除を要する票、要件の変更を伴う票は `false` にする。
  4. `depends_on` の票がすべて `merged` である。
  5. `files_allowed` が、同時に動く他のレーンの票と重ならない（重なれば後に回す）。
- **順番**：キューの並びのままである。オーナーが並べる。

起動の窓口（`launcher.sh`）から来た票は、オーナーが昼に承認した票なので、時刻の窓（`until`）と `unattended` の印を求めない（SPEC §5）。

## 3. 上限（決定論的。超えたら新しい票を取らない）

既定の値は `night-runner.sh` のコードにある。キューの `limits` と引数（`--parallel`・`--until`）で変えられる。

| 上限 | 既定 | 備考 |
|---|---|---|
| 並行の作業員 | **1（逐次）** | 並行は、キューの `parallel` で明示したときだけ（SPEC §9） |
| 1 晩の票 | 6 | 朝刊を読める量にする |
| 時刻 | 止める時刻 06:30 | `until` を過ぎると新しい票を取らない |
| 1 票の時間 | 票の `time_limit_min`（なければ 45 分） | 超えたら作業員を打ち切る |
| 作業員のトークン | 1 票 200 万、1 晩 1,200 万 | `claude -p --output-format json` の利用量を足す。読めないときは、上限を使ったものとして数える |
| 司法の呼び出し | 1 晩 20 回 | 夜に Z3 にできた判定のファイルを数える |
| 空き容量 | 3 GB 未満で停止 | |
| 課金 | 開発エージェントの契約の枠だけ | 利用上限の文言が出たら停止する。API キーには切り替えない |

作業員、judge、Codex、憲法審査の呼び出しは、予算の台帳の窓口（`metered.sh`）を通り、起動の前に予約が台帳に書かれる（SPEC §9）。

## 4. 1 レーン（1 票）の流れ

1. **worktree を作る**：`.claude/worktrees/night-T-NNN` に、`night/T-NNN` ブランチで作る。`.claude/worktrees/` の下なので、フックの閉じ込め（`agent_type` がなくても、cwd が `.claude/worktrees/` の下なら作業員として閉じ込める）がそのまま効く。
2. **作業員を起動する**：`cd <worktree> && claude -p --agent worker --output-format json --max-turns 80 …`。権限の確認が要る操作（依存の追加、push、`rm`、`npx`）は、無人では承認されず、拒否として作業員に返る（fail-closed）。無人では確認に答える人がいないので、night-runner は起動ごとに、票の `files_allowed` の Edit・Write と `git add`・`git commit` だけを `--allowedTools` で許可する。deny、フック、sandbox は変わらない。
3. **結果の前検査**：gate-runner の検査の一部を、night-runner が先に見る。コミットが 1 つ以上あること、差分が `files_allowed` の中であること、保護パスと秘密情報がないこと、テストが通ること。外れれば、報告を添えて**1 回だけ**やり直させる。2 回目も外れれば、その票は止めて、要約に書く。
4. **票を review にして main にコミットする**：night-runner は `status: review` と記録の 1 行だけを書き、`night-runner` の名前でコミットする。受け入れ条件（§2）は変えない。ソースに触らない。
5. **申請を置く**：`merge-requests/T-NNN.json`。統合キューにより、申請は複数同時に置ける。ブランチは main から分岐したままでよい（鎖で積まない。rebase も cherry-pick もしない）。
6. **結果を待つ**：夜は gate-runner を `--hold` で動かすので、合格しても統合されない。
   - **合格（held）**：gate-runner が候補を Z3 の `held.jsonl` に記録する。worktree とブランチは残す（朝の release が使う）。
   - **rejected**（差し戻し）：票の記録にある gate-runner の行を、作業員に渡して**1 回だけ**やり直させる。2 回目も落ちれば、そのレーンは止めて朝刊へ回す。差し戻しの回数は gate-runner が数える（上限 3）。
   - **blocked**（司法が重大な指摘で分かれた、保護パス、上限など）：何もしない。朝にオーナーが裁定する（`rule.sh`）。
7. **記録**：各レーンの `claude -p` の JSON（利用量、結果、終了コード）を、Z3 の `night/logs/<日付>/` に残す。票の本文以外の生のログは、リポジトリに入れない。

### 4.1 朝の統合

オーナーが画面と判定を確かめ、`vgdd/scripts/release.sh T-NNN …` で統合する。release は、今の main と申請の SHA から組み直し、入る変更が夜に判定した変更と記録以外で一字一句同じことと、組み合わせた木の監査（sandbox の中）を確かめてから統合する。同じことが確かめられなければ、統合せず、昼に申請し直す（SPEC §7-4）。

### 4.2 統合キュー

昼も夜も、各票は main から分岐したまま申請する。gate-runner は申請ごとに、最新の main に申請の SHA を merge した候補を一時 worktree で作り、検査と判定を候補に対して行う。合格すれば候補を fast-forward で統合する（夜は統合せず held に記録する）。検査の途中で main が進んでいれば、統合せず、次の周回で検査し直す。1 件統合するたびに、残りは最新の main と組み合わせて検査し直す。前の票が差し戻されても、後ろの票は止まらない。候補ごとに依存の取得と司法の呼び出しが走るので、検査し直しの分だけ司法の呼び出しが増える（§3 の上限で止まる）。

## 5. 止める条件

1 つでも当たれば、新しい票を取らない。動いている作業員は、時間の上限まで待って終える。理由は要約に書く。

| 条件 | 見方 |
|---|---|
| 夜間の停止 | Z3 の `night/STOP` がある |
| Kernel 全体の停止 | Z3 の `STOP` がある（`kernel-stop.sh`）。SPEC §8 |
| 仕様の未承認 | 票の指紋に承認がなければ、その票は作業員に渡さず飛ばす |
| git の設定の変更 | 共有の `.git/config` が基準値と違う |
| 時刻 | `until` を過ぎた |
| gate-runner が止まっている | プロセスが見えない。night-runner は起こさない |
| 違反の検知 | この夜の運転の開始より後に、`gate_events.jsonl` に `main_advanced_outside_gate` が出た（night-runner 自身の作者名のコミットを除く） |
| 拒否の急増 | 直近 10 分の `deny` が 30 件を超えた（票の設計か法律の不具合の疑い。朝に人が見る） |
| 連続の失敗 | 2 票続けて前検査か司法で落ちた |
| 容量 | 空きが `min_free_gb` 未満 |
| 利用上限 | 利用上限やレート制限の文言、または非 0 の終了コードが続いた |
| 予算 | 司法の呼び出し数、またはトークンの合計が上限に達した |

止まるのは「新しい票を取らない」だけである。申請済みのものは、gate-runner が昼と同じ条件で判定を続ける。ただし Kernel 全体の停止中は、gate-runner も申請を処理しない（SPEC §8）。

## 6. gate-runner との関係

- 役割の分離は昼と同じである。night-runner は配る、申請する、記録する。gate-runner は判定する、統合する。night-runner は merge しない。gate-runner は票を配らない。
- 共有するもの：`merge-requests/`（night-runner が置き、gate-runner が拾って `done/` に移す）、`gate_events.jsonl`（gate-runner が書き、night-runner が読む）、票の記録（gate-runner が差し戻しの理由を書き、night-runner が作業員に渡す）。
- 夜の gate-runner は `--hold` で動かす。判定まで行い、合格した候補を `held.jsonl` に記録して、統合しない。統合は朝にオーナーが release で行う。release は、版の印のない記録と、Codex を省いていないのに Codex の判定がない記録を統合しない（SPEC §6-5）。
- git の設定の穴への備え：night-runner、gate-runner、release は、リポジトリのフックと fsmonitor を読まない設定で git を呼び、`.git/config` を Z3 の基準値（`git-baseline.sh`）と照合する。作業員は `git config` を書き換えられない（フック）。

## 7. 朝刊

`morning-report.mjs` は、「集計（決定論的）→ ローカル LLM → Claude」の 3 段で朝刊を書く。ローカル LLM と Claude は書記で、決めない。実行用のコピーはオーナーが Z3 に置く。

1. **集計（node）**：`gate_events.jsonl`、`evidence/verdicts/`、`verify-chain.mjs --summary-json` の集計、`night/logs/`、票の盤を読み、件数、ID、時刻だけの要約にする。理由の本文は、票の記録への参照にする。
2. **ローカル LLM**：拒否の理由の分類と、差し戻しの理由の 1 行の言い換え。出力には必ずローカル LLM と付け、**件数と分類は参考**として扱う。小さなモデルは、同じ所で同じように間違う（特に否定の取り違え）。
3. **Claude（`claude -p`。ツールなし）**：集計とローカル LLM の下書きだけを入力に、固定の見出しで書く。見出しは、一晩の結果、統合された票、差し戻しと blocked と理由、法律やフックの気づき、朝に確認してほしいこと、である。規則：入力にない事実を書かない、ID を必ず引く、「〜ではない」を落とさない、判断（採否、合否）を書かない。
4. **置き場所**：Z3 の `night/reports/<日付>.md`。リポジトリには書かない。オーナーが読んで、公開してよいものだけを写す（生のログ、秘密情報、実名は含めない前提で、写す前に人が見る）。

朝刊の文章は LLM の出力である。数字は、集計の JSON から人が照合できるようにする。

## 8. 保証できないこと、限界

- 作業員は、無人でも同じフックと sandbox の下で動く。試験運転で、証拠ストアの記録を見て、無人の `claude -p --agent worker` のフック入力に `agent_type: worker` と worktree の cwd が入ることを確かめた（最初の導入先での確認）。
- 無人では許可の確認に答える人がいないので、確認待ちは拒否になる。night-runner は §4 の 2 の許可だけを渡す。`files_allowed` の外の変更は、前検査が落とす。
- night-runner は gate-runner と同じく、オーナーの権限のスクリプトである。バグで main が壊れる経路は、「票の status と記録のコミット」だけに限る（ソースは触らない）。夜は `--hold` なので、main にコードが入る経路は、朝の release だけである。
- **macOS 標準の bash 3.2 で動く前提**で書いている。バックグラウンドのレーンの関数の中で `command` を使うとレーンのプロセスが置き換わるため、git は起動時に決めた絶対パスで呼ぶ。`wait -n` は使わない。レーンの件数と記録は変数ではなく、その夜の出来事のファイル（`night/logs/<日付>/lanes-<run_id>.tsv`）に追記し、本体が数える。`end` のないレーンは「予期せず終わった」として記録し、失敗に数える。
- 開発エージェントの契約の枠の残りは API で読めない。利用上限の文言で止めるしかなく、止まった後の作業員の途中の作業は worktree に残る（朝に人が見る）。
- フックが動かなければ全操作が止まる。止まった呼び出しは証拠ストアに残らない。朝に、記録が途切れた時刻として気づく（[`vgdd-status.md`](vgdd-status.md) §2）。

## 9. 試験運転の計画（最初の晩）

最初の導入先で行った試験運転の計画である。このリポジトリでは、実際の無人の運転を試していない（適合性テストの N 群は、夜間の代行の規則を確かめる）。

| # | 確認 | 期待 |
|---|---|---|
| 1 | `--dry-run` で、キューの検査、レーンの割り当て、止める条件を表示するだけにする | 何も起動しない |
| 2 | 票 1 件、`parallel 1`、`until` を 1 時間後にする | 作業員が実装し、前検査、申請を経て、gate-runner が判定する |
| 3 | 証拠ストアに作業員の呼び出しが worktree の cwd で残り、閉じ込めの拒否が効く | §8 の最初の項目を確かめる |
| 4 | 差し戻し（故意に受け入れ条件を満たさない票）、1 回のやり直し、2 回目で止まる | 朝刊に「確認してほしいこと」が出る |
| 5 | `STOP` ファイルで止まる。gate-runner を止めても night-runner は merge しない | 停止の記録が残る |
| 6 | 朝刊が 3 段で生成され、数字が要約と一致する | 手動か、決まった時刻の起動 |
