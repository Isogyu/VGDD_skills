# 主張と証拠の対応（VGDD Governance Kernel、法律 p0.4.16）

VGDD について言えること（主張）を、規範（仕様）・判例（適合性テスト）・実運用の記録に結ぶ。**確かめた範囲**の列は、どの方法で確かめたかを分けて書く。「実装済み」と書いてよいのは、判例か実運用の記録で確かめたものだけ（憲法の約束4。憲法は導入先の `CLAUDE.md` で、このリポジトリにはない）。規範の正本は `vgdd/kernel/SPEC.md` と `vgdd/kernel/capabilities.json`。ここは案内で、規範を写さない。

- 試験の対象：法律 p0.4.16（`vgdd/kernel/capabilities.json` の `kernel_version`。下の表の実例の多くは p0.4.8 までの時点のもの）
- 適合性テスト：`node vgdd/conformance/run.mjs`（依存なし、Node 22 以上）。p0.4.16 の原本は 635/637（2026-11-14。不合格は p0.4.15 と同じ ST16 と M の1件で、このリポジトリに配置済みの設定がないことによる。設定の層の照合・入れ子の起動の拒否は公式の文書で確かめた仕様に基づき、実機では未確認）。p0.4.15 の原本は 589/591（2026-11-14。不合格の ST16 と M の1件は、このリポジトリに配置済みの設定がないことによる。稼働中の写しでは未実行）。p0.4.8 の原本は 414/414。稼働中の写し（`--impl z3`）は 2026-11-07 15:10 に 414/414（記録は Z3 にあり、公開の写しは `docs/governance/kernel-invariants.json` の `verified_by`）。p0.4.7 の時点は 410 件（11:08）、p0.4.5 の時点は 387 件（11/7 01:25 に稼働中の写しで 387/387）
- 実運用の記録：最初の導入先（この基盤を最初に運用した 1 つの開発案件）の、票の §6、票の盤、操作の集計（このリポジトリの `docs/governance/summary.json` は、その集計）。これらの元の記録は、このリポジトリにはない。証拠ストアと判定の本文は Z3 にあり、公開しない
- 番号について：最初の導入先の票の番号は使わず、実例は件数と内容で書く。`OBS-053` のような事象の番号は、最初の導入先の記録の番号で、元の記録はこのリポジトリにない（[`kernel.md`](kernel.md) の冒頭の断りを参照）

## 2. 正常な仕事の完了の流れ（最初の導入先での 1 票の例）

1. 行政の長の下書き → 立法補佐が法律の書き出しの形に合わせ、Codex の点検（13 件）を反映して、票として main に固定
2. オーナーが approve-spec → Kernel の写しで承認済みを確認 → 行政の長が作業員を worktree で起動
3. 申請 → 裁判所が最新の main と組み合わせた候補を検査（監査・judge・Codex・Codex security すべて APPROVED）→ held（夜間の運転での合格）
4. 立法補佐が候補を動かして画面を確認 → オーナーが release → main に統合（`status: merged`）

## 3. 状態の違いと、次に動く担当

| 状態 | 意味 | 次に動く担当 |
|---|---|---|
| 差し戻し（in_progress） | 監査か司法が不合格。上限3回 | 行政の長（作業員に直させて再申請） |
| 司法が使えない（申請が残る） | 判定が成り立たない。差し戻しではない。同じ申請で3回なら blocked | オーナー（司法の環境を確かめる） |
| 承認待ち（blocked、未承認） | 仕様の承認がない・承認の後に変わった | オーナー（approve-spec） |
| 分かれた（blocked） | judge と Codex が重大な指摘で分かれた | オーナー（裁定） |
| held | 夜間の合格。統合していない | オーナー（画面を見て release） |
| 停止中 | Kernel の STOP。停止の後に始まる操作を拒否 | オーナー（kernel-resume.sh で条件を確かめて再開） |

## 4. まだ確かめていないこと

- （済み）最初の導入先での停止（kill switch）の実演（K2）：2026-11-07 に、オーナーが kernel-stop.sh で止め、その 12 秒後に行政の長の Bash（`git status`）がフック p0.4.5 に「停止中」で拒否され、証拠ストアに記録された。統治の画面には停止中の表示が出た。約2分半後にオーナーが kernel-resume.sh で再開した（証拠の検証・git の設定・作業ツリー・main の前進なしを確かめた。証拠の検証で見つかった競合の形の食い違いは、注記として扱った）。p0.4.4 までは、この再開が証拠の検証の失敗で拒まれていた（p0.4.5 で直した）
